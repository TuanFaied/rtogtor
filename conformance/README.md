# Conformance suite

Language-neutral test data that **every** RtoGtoR implementation — the Go
engine and each SDK — must pass. A feature is "supported in language X" only
when X passes all of its cases.

## Vectors

| File | Spec | What implementations must do |
|---|---|---|
| [`vectors/identity.json`](vectors/identity.json) | [`identity.md`](../specs/identity.md) | Normalize each `key` to `canonicalKey`; reproduce `serializationHex` and `rtgId` exactly; fail each `invalid` case with exactly `errorCode` |
| [`vectors/values.json`](vectors/values.json) | [`values.md`](../specs/values.md) | Normalize each `valid` input to `canonical`; reject each `invalid` input with `errorCode` |

The identity vectors were generated by an independent reference
implementation (separate from the Go engine) from hand-specified canonical
forms; the engine reproduces them in `engine/ir/vectors_test.go`.

## Cases

| Case | Contents |
|---|---|
| [`cases/ecommerce/`](cases/ecommerce/) | `expected-schema-metadata.json`: inspection of `examples/ecommerce/schema.sql`, with server version, database name and row estimates removed |

Full end-to-end cases arrive in Milestone 2.

### Planned case layout

End-to-end cases will live in `cases/<case-name>/`:

```text
source.sql | source.cypher   input fixture
mapping.yaml                 mapping under test
expected-plan.json           canonical (RFC 8785) plan
expected-destination.json    normalized destination snapshot
expected-report.json         canonical report, including warnings
```

`runner-protocol.md` will define how each SDK's harness runs cases and reports
results.

## Changing vectors

Vectors change only together with the spec they test. Identity vectors for
`rtg-id/v1` are append-only: existing entries must never change.
